# Expansion to 150 levels + premium polish — plan of record

> **Durable reference** for the program that grows GRAVITY FLOW from **56 → 150 levels** and raises the
> whole app to a commercial polish level. Companion to `docs/project-status.md`. Started 2026-06-14.
> Approved decisions: **balanced interleave** (polish ↔ content milestones), **curate + author +
> validator** pipeline, **launch timing deferred** (no Play Console / store / signing work in this program).

## Why
The repo's own `2026-06-07-excitement-audit.md` is blunt: the game is a competent puzzle prototype that's
"emotionally flat and visually anonymous" — more *levels* is the lowest-leverage lever; spectacle, audio,
identity and a hook are what make it shareable/commercial. So this program **interleaves** content growth
with the polish the audit demands, rather than just piling on levels.

## Guardrails (inherited, non-negotiable)
- One entity class + one optional `LevelConfig` field per mechanic. **No managers.** Constants in config.
- **Never rewrite the inverse-square attractor formula** (tune `STRENGTH`/`MIN_DIST`/`MAX_DIST` only).
- `tsc --noEmit` + `npm test` + `npm run build` green at every milestone.
- **Don't delete retired levels** — promote/curate. Balance fairness still needs a human device playtest.

## Difficulty rubric (apply to every level)
From `2026-06-03-content-roadmap-100.md`, kept as the authoring standard:
- **goal.radius by role:** teach 40–52 · develop 34–40 · twist 30–36 · combine 26–32 · master 22–28.
- **parTimeMs** = a clean *expert* run (the 3rd star should demand a deliberate route).
- **collectible (gem)** = always genuinely **off-route** (a detour / a risk past a hazard or repeller).
- **Per-world 10-level arc:** Teach×2 → Develop×2 → Twist×1 → Combine-with-prior×3 → Master×1 → Boss.
- **Tension** (hard-fail hazards/timeouts) concentrated in designated worlds; elsewhere difficulty comes
  from precision/routing + the 3-star layer. **1★ always achievable** with the world's taught skill.

## ⚠️ worlds.ts deviation from the original plan
The original plan said "extend `WORLDS[]` to the 15-world skeleton now." **We are NOT doing that**, because
renumbering worlds to 10-wide while only 56 levels exist would mis-group the live campaign (e.g. Currents
levels would show under "Foundations"). Instead: **`worlds.ts` always stays in sync with real content** and
grows in each *content* milestone (M2/M4/M6). The validator enforces `lastWorld.to === LEVELS.length`, so
the build is always internally consistent. The 15-world layout lives in this doc until its levels exist.

## ⚠️ Mid-program finding (2026-06-14): polish is far more built than the audit implies
The `2026-06-07` excitement audit predates a large polish push. Verified in source, the game ALREADY has:
per-world visual identity (`config/worldThemes.ts` — palette/nebula/star-tint/accent/subtitle, wired into
`CosmicBackground` + `GameScene` title cards), per-world adaptive music + a boss minor bed
(`AudioSynth.startWorldTheme` / `playBossClear`), and a rich win celebration (star-by-star tones,
PERFECT!, camera punch + shake, boss "STAR FREED", arrival-cosmetic bursts, achievement toasts). So the
planned **M1/M3 polish milestones largely duplicate existing systems** — re-building them would waste
effort and risk regressions. **Re-weighting:** lead with CONTENT (the genuine gap), and keep polish to
*targeted, verified-missing* additions only (audit each scene during content work). M5 stays mostly intact
(reward flair / hook / transitions are genuinely lighter than the world-identity system).

## Validator (M0, shipped)
`src/config/levels/levels.test.ts` runs in `npm test`. Asserts: ball/goal/pickups/mechanic-anchors in
bounds; ball not in a wall or static hazard; goal not buried in a wall; goal radius in [16,60];
`timeLimitMs > parTimeMs`; world ranges contiguous from 1 and `lastWorld.to === LEVELS.length`. It is a
**trap-catcher, not a solver.**
